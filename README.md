# Student & Flow - практика ООП на Java

Учебный проект: обобщённая модель студента с валидацией и отменой действий, плюс собственная мини-реализация ленивого потока данных в духе `java.util.stream`.

**Стек:** Java 25 · Maven · JUnit 5 · JaCoCo (покрытие ≥ 80%, проверяется при сборке) · JavaDoc

## Что внутри

### `Student<T>` - студент с оценками произвольного типа
- Тип оценки задаётся параметром: числа, строки («зачет»/«незачет»), даты и т. д.
- Правило корректности оценки передаётся как `Predicate<T>` при создании и не меняется. Некорректная оценка → `InvalidGradeException` (unchecked).
- **Отмена действий** (`undo()`) - паттерн «Команда»: каждое успешное изменение кладёт в стек лямбду, которая умеет его откатить. Копии состояния не хранятся, неудачные операции в историю не попадают.
- Инкапсуляция: `getGrades()` возвращает копию, входные списки копируются.
- `equals`/`hashCode`: два студента равны, если совпадают имя и мультимножество оценок (порядок не важен, кратность важна).

```java
Student<Integer> s = new Student<>("Андрей", x -> x >= 2 && x <= 5);
s.addGrade(5);
s.setName("Артём");
s.undo();                 // имя снова «Андрей»
s.addGrade(7);            // InvalidGradeException
```

### `Flow<T>` - ленивый поток данных
- Фабрики: `of(List)`, `of(T...)`, `iterate(seed, step, condition)`.
- Промежуточные операции `map` (с возможной сменой типа) и `filter` работают за O(1): они только запоминают функцию.
- Все вычисления выполняются за один проход в терминальных `reduce` и `collect`, без промежуточных коллекций. `iterate` генерирует значения по требованию.

```java
Flow.of(1, -2, 3).filter(x -> x > 0).reduce(Integer::sum);          // 4
Flow.iterate(1, x -> x * 2, x -> x < 100).reduce(Integer::sum);     // 127
List<String> s = Flow.of(1, 2, 3).map(x -> "#" + x)
                     .collect(ArrayList::new, List::add);           // [#1, #2, #3]
```

## Тесты

58 тестов JUnit 5, сгруппированных по требованиям через `@Nested`: контракт `equals`, валидация, порядок и полнота отмены, ленивость `Flow` (проверяется счётчиками вызовов), повторное использование потока, граничные случаи (пустой поток, `null`-элементы).

## Проектные решения и ограничения

- `map` и `filter` возвращают **тот же** объект `Flow` (требование задания). В отличие от `java.util.stream`, это значит, что после `map` со сменой типа старую ссылку использовать нельзя.
- **Известное ограничение:** `Student.equals` сейчас сортирует оценки, поэтому работает только для типов, реализующих `Comparable`. План исправления - сравнивать частотные словари (`Map<T, Long>`). Это снимает требование `Comparable` и сохраняет согласованность с `hashCode`.
